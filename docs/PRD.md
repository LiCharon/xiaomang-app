## Problem Statement

短视频内容团队需要同时服务多个客户。项目经理负责了解客户 IP、分析对标账号、确定内容策略、分配任务和复盘效果；员工负责找选题、提取真实脚本、二创、准备封面与发布材料。现有工作容易被分散在沟通纪要、表格、平台后台、AI 对话和交付文档中。

这带来六类问题：

1. **客户信息难以持续复用。** 原始沟通材料和结构化 IP 信息脱节，员工在写稿时可能遗漏客户经历、产品优势和目标用户，产生与客户定位不符的内容。
2. **对标分析难以沉淀。** 选题分类、前三秒、结尾钩子各自分析，缺少客户级知识库与来源记录，员工重复抓取、重复转写、重复判断。
3. **内容生产难以保持策略一致。** 员工只看到单条热门视频，缺少明确的大小类配比与结构优先级，容易持续生产同一种选题。
4. **交付材料易串稿或漏项。** 二创脚本、标题、开场、封面、发布文案和标签分散处理，切换选题后可能误用其他视频的结果，导出时难以检查是否完整。
5. **数据复盘不能影响下一轮。** 能看到播放量，却难以按选题大类/小类及三秒、标题、结尾标签解释表现，更难把经理认可的经验落实为下周可执行的配比。
6. **数据可信度与权限容易被忽略。** AI 可能将发布文案当成完整脚本、编造受众和商业信息，或对缺失指标填零；共享客户名册与个人报告也可能被错误地使用同一种权限规则。

产品要解决的是从“知道客户是谁”到“生产符合定位的内容”，再到“根据真实反馈调整下一轮”的团队协作闭环。

## Solution

### 产品目标

小芒将客户信息、对标研究、内容资产、生产任务和自有账号表现连接在同一工作台中。经理制定并确认策略，员工按照客户与平台执行；系统负责数据获取、结构化处理、确定性计算和 AI 辅助分析，重要经验经过经理确认后再进入下一轮。

本版本目标：

- 让已确认的客户 IP 信息能够用于账号规划和内容生产。
- 将对标样本转为可追溯、可复用的正式选题库与结构类型统计。
- 将选题、二创、发布材料和最终编辑连成清晰的交付流程。
- 让 4.1、4.2 可直接填表，也可上传 Excel 并用 AI 辅助识别。
- 将周度分析变成具体的下周选题与结构配比，经过经理确认后自动被相关生产环节读取。
- 让缺失数据、弱证据、未完成抓取与外部服务失败对用户可见。

### 角色与工作分工

| 角色 | 主要责任 | 权限原则 |
|---|---|---|
| 项目经理 | 客户建档、IP 信息确认、员工和任务管理、对标研究、建库、账号规划、周报与配比确认 | 可使用管理端和内容工作台；报告与确认历史按所属经理控制 |
| 内容执行员工 | 查看本人任务、读取客户生产资料、筛选视频、二创、发布材料准备、单条视频分析 | 可使用内容工作台；不得修改经理专属报告、正式库和生效复盘策略 |
| 客户/IP | 提供原始经历、业务信息、参考素材及自有账号后台数据 | 当前通过经理或员工录入，不设置独立客户端角色 |

### 产品结构与主流程

账号定位包含四个模块、两层关系：

| 模块 | 子功能 | 关系与产出 |
|---|---|---|
| 模块 1：对标账号分析 | 1.2 对标账号分析 | 复用选题库构建的研究结果，形成商业、用户和内容定位等报告 |
| 模块 2：账号规划 | 1.3 账号规划 | 直接使用客户 IP 档案与 1.2 报告，形成可审核修改的规划 |
| 模块 3：选题库构建 | 2.1 分类、2.2 黄金三秒、2.3 结尾钩子、2.4 正式选题库 | 为其他模块提供研究资产与类型词典；内部子步骤不能当成与 1.2/1.3 平级的阶段 |
| 模块 4：复盘分析 | 4.1 视频数据分析、4.2 账号数据分析 | 分析自有账号真实数据，形成建议；经理确认后回流选题与二创 |

主流程：客户/IP 建档 → 经理分配客户任务 → 构建对标研究与正式选题库 → 形成账号定位和规划 → 员工筛选选题并二创 → 发布仓核查与导出 → 最终文案编辑 → 人工发布并取得后台数据 → 单条/周度复盘 → 经理确认配比及经验 → 下一轮选题与二创。

研究与账号规划可按依赖关系复用已有报告，不要求每个任务重新执行所有步骤。正式客户任务与员工临时分析是两种入口，临时分析不强制创建客户。

### 领域术语

| 术语 | 定义 |
|---|---|
| 客户 | 团队服务的业务对象，承载 IP 信息和生产资产的关联标识 |
| IP 档案 | 原始沟通纪要及身份、产品、用户画像等结构化信息，具有审核状态和版本 |
| 对标账号 | 用于研究的外部参考账号，与客户自有账号分开 |
| 自有账号 | 客户实际运营并提供后台视频数据的账号，是复盘分析对象 |
| 正式选题库 | 客户关联的对标研究资产，保留各账号分类及来源分析，供新视频打标签和二创读取 |
| 大类/小类 | 内容主题的两层分类，小类隶属于特定大类；名称相同不代表来源账号相同 |
| 黄金三秒/3s | 文案开场结构与类型分析；真实转写范围与文案中“前三秒”的产品称呼区别记录 |
| 结尾钩子 | 视频结尾承担互动、转化、反转或记忆点等作用的文本结构 |
| 待人工复核 | 证据不足或不能可靠分类的结果，属于待处理队列，不属于参与配比的内容类型 |
| 发布仓 | 为具体选题准备、选择、核查与导出封面、发布文案和标签的工作区 |
| 配比 | 某组内容或结构类型的百分比分布；研究样本的观测配比与下周执行建议必须分开 |
| 复盘记忆/经验 | 经理确认后的配比及文字经验，具有不可变版本和当前生效指针 |

### 成功衡量

以下是后续验收和产品运营的衡量口径，不是已验证的增长承诺，也不代表已实现完整埋点：

| 指标 | 衡量方式 | 本版验收要求 |
|---|---|---|
| 核心流程可完成性 | 按指定客户完成建档、研究、选题、二创、材料交付与复盘的业务场景 | 验收样例可完整完成，不因缺少 Excel 或 AI 失败失去手工路径 |
| 客户上下文一致性 | 检查各页面和导出材料的客户、任务、选题关联 | 验收场景中无跨客户、跨选题串用 |
| 策略回流正确性 | 对比确认前后及停用后的选题配额和结构读取 | 只有确认的版本生效，停用后可回退 |
| 数据可追溯性 | 抽查分析值、原始单元格、真实脚本来源和有效样本 | 统计可复算，来源或缺失可解释 |
| 团队效率 | 记录研究、写稿、导出和周报耗时及重复操作次数 | 先收集人工基线，再确定效率目标，不预设无依据的节省比例 |
| 内容效果 | 按客户与平台观察播放、留存、互动等周度变化 | 用于持续观察，不将相关性直接承诺为播放增长因果 |

## User Stories

### 登录、员工与任务管理

1. 作为项目经理，我希望使用统一登录进入经理端和内容工作台，以便不必维护两套工作身份。
2. 作为项目经理，我希望通过有效邀请码注册，以便团队能够控制管理账号的创建。
3. 作为员工，我希望通过分配的员工账号登录，以便进入适合我角色的工作台。
4. 作为登录用户，我希望菜单只显示我有权访问的功能，以便理解自己的工作范围。
5. 作为登录用户，我希望退出后清除当前用户的工作缓存，以便下一位使用者不会看到我的草稿。
6. 作为项目经理，我希望创建、编辑和停用员工账号，以便维护团队成员与工作资格。
7. 作为项目经理，我希望有在用任务的员工不能被误删，以便保留任务负责人关系。
8. 作为项目经理，我希望为员工或经理指定任务负责人，以便灵活安排执行工作。
9. 作为项目经理，我希望单条或批量创建客户任务，以便减少重复安排。
10. 作为项目经理，我希望设置客户、平台、合作周期、优先级及内容要求，以便员工明确执行范围。
11. 作为项目经理，我希望按负责人、平台、状态及日期筛选任务，以便掌握团队工作。
12. 作为项目经理，我希望按北京时间查看当天合作期内的任务，以便按统一日期安排工作。
13. 作为员工，我希望查看分配给自己的任务，以便直接进入当天需要处理的客户内容。
14. 作为员工，我希望从任务进入后携带客户信息，以便后续选题和二创不会丢失业务上下文。
15. 作为员工，我希望在任务交付完成后更新任务状态，以便经理知道工作进度。
16. 作为员工，我希望可以发起不关联客户的临时分析，以便先研究素材而不污染正式客户资产。

### 客户与 IP 档案

17. 作为项目经理，我希望维护客户基本信息和参考账号，以便建立稳定的客户名册。
18. 作为项目经理，我希望粘贴沟通纪要或导入支持的文档，以便减少重新整理客户资料的工作。
19. 作为项目经理，我希望让 AI 从原始材料整理 IP 信息，以便快速得到可审核的结构化初稿。
20. 作为项目经理，我希望分别编辑身份、产品和用户画像信息，以便保留客户真实特点。
21. 作为项目经理，我希望保存草稿或标记待复核，以便信息不完整时仍可继续采集。
22. 作为项目经理，我希望看到缺失的最低确认条件，以便补齐姓名/昵称和原始沟通纪要后确认建档。
23. 作为项目经理，我希望确认 IP 档案后形成版本，以便下游能够辨认所用资料。
24. 作为项目经理，我希望并发修改档案时收到冲突提示，以便避免覆盖他人的更新。
25. 作为项目经理，我希望历史客户资料能兼容进入新档案，以便保留已有客户积累。
26. 作为员工，我希望任务携带相应 IP 档案快照和版本，以便知道本次生产依据。
27. 作为内容生产者，我希望未经证实的价格、受众或经历保持为空或待核实，以便不对外输出虚构事实。

### 选题库构建与对标研究

28. 作为项目经理，我希望选择对标账号及口播/演绎模式，以便按适合的内容逻辑分析。
29. 作为项目经理，我希望抓取对标账号最新 60 条作品，以便使用清晰一致的研究样本范围。
30. 作为项目经理，我希望抓取不足、分页未完成或账号无法识别时得到提示，以便判断报告完整性。
31. 作为项目经理，我希望查看大类、小类及具体视频的分类树，以便理解账号内容构成。
32. 作为项目经理，我希望标记重点研究视频，以便保留需要进一步观察的样本。
33. 作为项目经理，我希望保存、回看和删除自己的分类报告，以便复用研究结果。
34. 作为项目经理，我希望分析每条样本真实的开场文案和三秒类型，以便学习可复用的开场结构。
35. 作为项目经理，我希望看到各大类中的三秒分布及常用类型，以便区分不同内容需要的开场方式。
36. 作为项目经理，我希望单独提取结尾真实口播，以便避免使用开头转写推断结尾。
37. 作为项目经理，我希望看到五类结尾钩子的分布和原因，以便学习互动与转化等结构。
38. 作为项目经理，我希望分清转写文本和发布文案来源，以便识别研究证据的可靠程度。
39. 作为项目经理，我希望证据不足的样本进入待人工复核，以便避免将不确定分类计入配比。
40. 作为项目经理，我希望将三份研究结果关联到客户正式选题库，以便员工持续使用同一研究资产。
41. 作为项目经理，我希望一个客户库可纳入多个对标账号并保留各自分类，以便避免丢失来源语义。
42. 作为项目经理，我希望同一来源重复纳入时不产生重复账号，以便保持库的可维护性。
43. 作为项目经理，我希望移除对标账号或删除库时有明确作用范围，以便控制知识资产。
44. 作为员工，我希望读取客户的正式库及标签词典，以便对近期新视频使用已有分类。
45. 作为员工，我希望不能修改经理管理的正式库，以便团队研究基准不被执行过程误改。

### 账号分析与规划

46. 作为项目经理，我希望基于对标账号的现有研究生成综合分析，以便理解其商业定位、核心痛点、内容与运营策略。
47. 作为项目经理，我希望可以分析新的参考账号，以便不受历史报告列表限制。
48. 作为项目经理，我希望报告区分可观察事实、推断与待验证信息，以便对客户做有依据的判断。
49. 作为项目经理，我希望结合客户 IP 档案和对标分析形成账号规划，以便将研究转为执行方向。
50. 作为项目经理，我希望审核和修改规划内容，以便把实际业务经验纳入方案。
51. 作为项目经理，我希望保存规划及导出支持的报告格式，以便向团队或客户交付。
52. 作为员工，我希望按客户读取团队可用的账号规划，以便二创符合客户方向。
53. 作为项目经理，我希望员工只能按客户使用规划而不能修改或遍历我的私人报告，以便兼顾协作与权限。

### 选题筛选与内容二创

54. 作为员工，我希望选择客户及平台后读取库内账号近期更新，以便快速发现新素材。
55. 作为员工，我希望只将点赞严格超过 100 的视频纳入既定更新筛选，以便保持当前选题门槛。
56. 作为员工，我希望调整允许的近期窗口并看到抓取进度，以便知道本次素材范围。
57. 作为员工，我希望抓取失败时可以继续未完成部分，以便避免重复获取全部素材。
58. 作为员工，我希望按视频逐条获得脚本与分类结果，以便先处理已完成内容。
59. 作为员工，我希望系统复用已有真实脚本，以便不为二创重复转写同一素材。
60. 作为员工，我希望看到转写失败、媒体不可用或仅有发布文案的提示，以便决定人工补充。
61. 作为员工，我希望标签来自客户库且不臆造不存在的类别，以便选题可以按库内口径归类。
62. 作为员工，我希望未完成标签处理的进度按本人保存，以便稍后继续自己的工作。
63. 作为员工，我希望勾选的参考视频进入本次二创而不自动改写正式库，以便区分研究资产与执行素材。
64. 作为员工，我希望根据客户 IP 和账号规划进行二创，以便内容体现客户身份与业务目标。
65. 作为员工，我希望分别选择或调整开场、标题、主体和结尾候选，以便组合成可用脚本。
66. 作为员工，我希望每组结构候选按配比换算为十条，以便选择时有可执行的类型分布。
67. 作为员工，我希望阅读并修改生成内容，以便控制事实、语气和表达质量。
68. 作为员工，我希望不同选题各自保存生成结果和选中内容，以便切换选题时不会串稿。
69. 作为员工，我希望系统优先读取已生效的复盘策略，以便本周生产能体现上周结论。
70. 作为员工，我希望库或记忆缺失时明确回退到可用基准，以便继续工作并理解建议来源。

### 发布仓与最终交付

71. 作为员工，我希望进入发布仓后按选题准备封面、文案和标签，以便形成完整交付材料。

## Implementation Decisions

### 1. 产品架构与权限边界

1. 保留一个前端工作台和统一身份认证。经理可进入管理端与内容生产端，员工仅进入其被允许的生产功能。
2. 保留账号定位的四模块、两层关系。模块 3 是研究资产底座；模块 1 直接复用模块 3；模块 2 直接复用 IP 档案与模块 1；模块 4 提供经确认的生产反馈。
3. 管理客户、员工和正式任务的入口为经理权限；员工通过本人任务和允许的客户上下文接口读取生产所需信息。
4. **客户名册当前为公司共享，不能在 PRD 中描述成完全按经理隔离的 SaaS 租户。** 报告及多数研究资产按经理控制，员工临时分析与标签进度按用户私有，生效复盘方案按客户和平台供团队读取。各对象沿用对应规则。
5. 员工读取账号规划只开放按客户的业务读取，不开放遍历经理全部报告、按任意报告 ID 获取正文或写入规划。
6. 4.1 对允许的登录用户开放，报告按既有归属管理；4.2 分析、周报管理、配比确认/停用为经理权限，员工只读对应客户和平台的生效方案。前端隐藏操作不能替代后端校验。
7. 客户关联从任务或正式生产入口传递。临时分析保持个人工作区，不自动写入客户库或团队经验。

### 2. 客户 IP 档案与任务

- 档案包含原始沟通纪要、身份信息、产品信息和用户画像。AI 可辅助抽取，用户负责核对与确认；不补写材料不存在的职业经历、价格、受众收入和案例。
- 档案状态为草稿、待复核、已确认；无档案可显示未开始。确认最低条件为姓名/昵称与原始沟通纪要，其他字段不强制一次补齐。
- 确认产生版本，更新记录操作者和时间；并发修改使用更新时间检查，冲突应返回可识别的提示。
- 正式任务记录负责人、客户、平台、合作起止时间、内容要求、优先级及所用 IP 快照/版本。状态为待处理、进行中、已完成。
- 当天任务按北京时间及合作周期筛选，不混用浏览器或服务器本地时区。
- 客户重复建档、无效负责人、无效日期、重复员工账号和在用员工删除均必须给出明确反馈。

### 3. 数据获取与对标研究

- 分类研究使用最新 60 条作品，不自动改成最近三个月；员工近期选题抓取的时间窗口是另一种规则。
- 口播类与演绎类使用不同分类语义。口播关注关键词、内容功能和文案；演绎关注场景、人物关系和冲突。
- 对标研究中的重点样本勾选只标记研究重点，不自动成为正式库条目，也不自动写入员工任务。
- 开场、结尾及完整脚本是三种不同提取范围；分别记录来源并隔离转写缓存，禁止用开场缓存代替结尾。
- 平台发布文案不是完整视频脚本。真实转写失败时可降级为发布文案，但必须标注来源和低置信度，不编造对白、场景和剧情。
- 账号和视频身份依据对应数据提供方验证，抓取不完整、媒体缺失、限流和转写失败可见。兼容已有数据来源，不扩大为所有平台均有同等分析能力。
- 黄金三秒使用既有八类标签体系；结尾使用引导互动、引导转化、反转、金句、共鸣＋IP 符号五类。标签定义由后端统一提供。
- 研究报告中的分布是基于有效样本的观测事实。待人工复核不参与配比；观察分布不得悄悄替换为模型建议分布。

### 4. 正式选题库与账号规划

- 正式库关联客户与所属经理，纳入分类、黄金三秒和结尾研究资产。多个账号保留独立分类 ID 和来源，不凭名称直接覆盖或合并原始账号分类。
- 在跨账号的复盘比较中，可按统一词典归并同名业务标签；归并分析不改写原始库的分类与样本。
- 新视频标签必须使用库内已有类别，证据不足进入待复核。勾选用于当次二创，不自动修改正式库。
- 更新筛选门槛为点赞数严格大于 100；刚好 100 不通过。保持进度可见、部分成功可用和未完成请求可继续。
- 1.2 综合分析区分事实、推断和待核实信息；商业、价格及受众画像无证据时留空或明确说明。
- 1.3 的直接输入为客户 IP 档案与 1.2 报告，规划可人工修改后保存并供相关生产流程读取。

### 5. 内容二创、发布仓与交付

- 二创按客户、平台和具体选题组织，复用已取得的真实脚本及正式库词典。
- 开场、标题、主体与结尾候选各自可选择修改；需要配比的结构由后端归一化并换算到十条候选，模型只生成相应内容。
- 有生效记忆时优先读取对应大类的三秒、标题和结尾配比，并加入经理确认的经验。没有记忆时使用已有库基准；缺少某组基准时如实提示。
- 发布仓保留封面、发布文案、发布标签及核查导出四部分，最终文案编辑仍保留在后续流程。
- 封面类型包括固定封面模板、背景变化及人像表情变化等既有方案。客户基底与每期候选分开，切换类型保留资产，根据类型检查实际需要的模板/人像。
- 封面生成输出实际图片，候选可连续修改与删除。异步请求固定发起时的选题、类型和参考素材，切换页面或选题不能导致结果串用。
- 发布文案中的标题和三秒复用二创选择结果；金句与互动文案使用 AI 生成候选。账号恒定标签与当期选题标签分开确认。
- 核查后导出或写入配置好的飞书目的地。写入是用户明确触发的交付动作，不在生成时自动执行；失败保留可交付材料。
- 任务完成表示团队交付流程的完成，不代表已自动向短视频平台发布。

### 6. 4.1/4.2 统一表单与 Excel 识别

| 要求 | 产品契约 |
|---|---|
| 默认入口 | 直接填写表单，不要求上传文件 |
| 视频信息 | 标题、链接、发布时间、文案、内部视频标识，以及选题大类/小类和三秒/标题/结尾类型 |
| 单条与周度 | 4.1 一次分析一条；4.2 可增删视频，一次 1～120 条 |
| 周度上下文 | 客户、平台、自有账号名称、连续七天范围、下周计划条数 |
| 必填值 | 播放量；周度另需发布时间。其余缺失值保持为空，不伪装成零 |
| 平台字段 | 按抖音/视频号显示指标与含义。抖音 2s 跳出率与视频号 3 秒以上播放率不能互相替代 |
| 支持文件 | `.xlsx` / `.xlsm`；旧 `.xls` 提示另存为 `.xlsx` |
| 导入方式 | 保留手工列映射；增加 AI 识别并填入可编辑表单 |
| 表格布局 | 支持每视频一行或一列，以及表头前有说明的布局；选择具体工作表 |
| AI 职责 | 仅定位方向、表头、字段位置、数据范围和应排除位置，不生成单元格数据 |
| 后端职责 | 从原始单元格读值，校验索引和平台字段，拒绝重复/越界映射，处理单位与日期 |
| 比例/数量 | 支持原始百分比、Excel 百分比格式、常见数字写法及明确的万单位；单位无法验证时保留原值并提示 |
| 汇总与截取 | 汇总/平均/说明记录跳过并提示，截取范围与遗漏风险显示给用户 |
| 核对与修改 | 显示来源字段和识别提示；导入会替换当前表单，修改后的表单值作为分析输入 |
| 失败行为 | 识别失败不清空已有表单；仍可直接填表或按列映射导入 |
| 边界限制 | AI 识别工作表最多 600 行、80 列；长表采样定位后读取原表，超限要求拆分；不能宣称任意布局都可可靠识别 |

表单字段、单位含义、类型词典和平台判定由统一后端元数据驱动。Excel 识别是数据录入辅助，不能代替用户对原始数据和单位的确认。

### 7. 单条视频分析

- 分析对象为客户自己发布的视频，不是对标库视频。数据由用户从平台后台获得并填写或导入。
- 展示直观指标、专业指标、解释、实测值、标准值及判定，映射到选题、三秒、标题和结尾四类结构。
- 互动率等派生值由后端根据有效输入计算，不能由模型提供计算结果。零播放等场景不能产生无意义除法结果。
- 结构结论包括可复用、需要优化和证据不足等既有语义；模型基于真实标题/文案解释原因和建议。
- AI 未返回有效建议时展示待人工补充，确定性指标分析仍可使用。保存报告不直接激活周度经验。

### 8. 周度统计与流量池

| 播放区间 | 处理原则 |
|---|---|
| 50～200 | 账号状态异常档，结合数据提出核查方向 |
| 500～1000 | 基础流量池，1000 归此档 |
| 大于 1000 且不超过 10000 | 有爆款潜力，分别分析高于/低于平台标准的结构表现 |
| 大于 10000 | 爆款档，结合文案与指标拆解可复用因素 |
| 小于 50，或大于 200 且小于 500 | 需求未定义的区间，参考归档并提示，不擅自补出正式流量池规则 |

- 绝对分析分别呈现 `>1000`、`<1000`、`=1000`，并列出对应的大类、小类和结构表现。此划分与流量池标签分别计算。
- 相对分析包括所有大类的比较、每个大类内部的小类比较，以及每大类中的三秒、标题、结尾类型比较。
- 展示日趋势和前周环比。前周仅选相同经理、客户、平台、账号名称的前七天已保存报告，缺少可比报告时不制造环比。
- 重复视频 ID 拒绝分析，日期无效要求修正；周期外、缺失/负播放量等不合格记录列入排除清单。缺失专业指标只减少相应指标的有效样本。
- 互动/完播等比例按有效播放量加权，越界比例不进入均值。显示有效样本数、缺失数和小样本提示。
- 数据体现关联关系，不能将结构类型宣称为播放差异的唯一原因；发布较近的视频需提醒观察时长不足。

### 9. 下周配比、确认版本与回流

1. 配比建议由后端确定性计算，AI 负责标签辅助与解释文字。人工已有标签优先，缺标签只能依据真实标题或脚本补全，不能依据播放量猜出文案类型。
2. 基准优先读取生效记忆；无记忆时选题使用本周有效分类分布，结构使用既有库基准，再回落到本周有效标签分布。当前标题的初始库基准沿用三秒来源，确认后作为独立维度调整，不宣称已存在独立标题研究库。
3. 选题评分结合相对账号播放中位数及相对同流量池互动率，单项倍率限制为 0.5～2；结构表现使用可复用 1.25、需优化 0.75、其他 1 的既有规则。
4. 调整倍率为 `1 + n/(n+3) × (评分−1)`，不足三条标为弱证据；无样本不推断类型表现。算法是本版产品基线，可后续验证效果，不能将其描述为用户给定的唯一数学规则。
5. 每组百分比归一化到 100%，最大余额法换算条数：大类总条数等于下周计划，小类总条数等于所属大类条数，结构候选合计十条。示例配比未满 100% 时不可悄悄丢弃余额。
6. 无样本且无基准的组不编造配比；经理可补充并预览。人工修改不得使用无效负值或产生无法解释的总量。
7. “生成分析”“保存周报”“预览配比”“确认生效”是不同动作。保存不会改变当前策略；确认需要已保存报告、审核后的配比和可选经理经验。
8. 确认产生不可变版本并切换当前指针。重复请求保持幂等，旧请求不能覆盖更晚版本，也不能复活已停用版本。
9. 生效范围是**客户＋平台**，不是账号名称。账号名称用于报告区分和环比；当前同平台多自有账号需要分别绑定客户。不得写成已实现多账号独立记忆。
10. 原始库统计不改写。员工按生效大小类配额勾选，不足时报告具体缺额，不用其他类别偷偷补齐；二创独立读取三秒、标题、结尾配比及经理经验。
11. 停用后回退到原有基准。删除来源周报不删除已确认经验，历史确认记录和当前指针分开管理。

### 10. 持久化与 API 契约

- 客户/IP、任务、报告、正式库、发布材料与复盘记忆分别持久化，通过稳定 ID 关联，避免整份复制造成上下文漂移。
- 报告列表返回元数据，正文按 ID 获取；查询、删除和修改均验证对象归属。保存及确认按对应指纹/请求标识幂等。
- 周度复盘分开保存分析报告、不可变记忆版本和生效指针，使用唯一约束防止重复版本与同范围多个当前指针。
- 新复盘接口保持四类职责：输入元数据/Excel 识别、周度分析、周报 CRUD、记忆预览/确认/读取/停用。错误应明确区分未登录、无权限、无效输入、对象不存在、并发冲突及服务不可用。
- 本地 Express 和 Vercel 入口复用业务层，字段、鉴权、计算与错误语义保持一致，不能只修改一种运行方式。
- AI 输出进入页面或持久化前先做结构校验和归一化；统计、标准值、类型定义及配比只有一个权威来源。
- 外部密钥只存服务端配置。分析内容、身份信息和缓存不得跨用户泄露；日志不得输出完整凭据。

### 11. 非功能要求

- 以桌面团队工作为主要场景，390px 手机宽度保持可操作、可阅读，无页面横向溢出或运行异常。
- 表单具备可识别字段名、指标含义、错误提示与加载状态；长耗时调用应防重复提交，并保留已经取得的可用结果。
- 抓取、转写、AI、图片生成和飞书等外部服务失败时提供可理解的状态，不伪装完成；录入与确定性复盘尽量保持可用。
- 页面切換与异步完成不得串客户、串选题；已支持草稿的研究阶段保留草稿，退出清理。不能据此承诺所有新表单都已实现跨刷新自动保存。
- 性能验收以典型 60 条研究样本和最多 120 条周度样本为范围；记录耗时、错误率及外部调用量，未取得基线前不承诺固定秒数。
- 构建、数据测试、API、真实渲染与浏览器交互分别验收。构建成功不能代替类型检查或证明完整流程可用。

## Testing Decisions

### 验收层级与原则

用户已确认：以**真实页面业务流程和 API 外部行为**为主要验收层级，覆盖客户权限、选题→二创→发布仓→复盘及确认回流；统计与 Excel 取值做独立边界验证。

- 测试用户能看到的结果、对象归属、保存状态、可复算数据与错误恢复，不断言内部函数调用顺序或组件私有状态。
- 优先复用现有路由契约检查、独立 Mongo 测试库、前端真实渲染检查及浏览器操作流程。数据库隔离在测试环境中完成，验收结束清理测试数据和服务。
- 浏览器测试覆盖事件处理、平台切换、导入后修改、异步请求及移动布局；静态或服务端渲染检查仅用于发现页面渲染错误。
- 外部模型协议模拟用于验证取值、状态与失败降级。真实账号、真实文案和真实 Excel 的模型质量另行验收，不能用模拟结果宣布模型效果通过。
- 金额、百分比、日期、阈值和条数优先检验最终报告/预览，不重复测试纯粹的实现细节。

### 主要验收场景

| 编号 | 场景与操作 | 可观察的通过条件 |
|---|---|---|
| AC-01 | 经理/员工登录、访问页面与 API、退出后换用户 | 菜单与后端权限一致；禁用员工不能进入；无上一用户草稿泄露 |
| AC-02 | 录入 IP 材料、保存草稿、补最低条件并确认 | 草稿可保存，缺必填有提示；确认产生版本，任务取得对应快照 |
| AC-03 | 两人修改同一 IP 档案 | 较旧提交得到冲突提示，不静默覆盖新内容 |
| AC-04 | 创建不同负责人任务并查看今日任务 | 客户/平台/合作期正确；员工看到本人的任务，北京时间日界正确 |
| AC-05 | 抓取研究样本并使用两种分类模式 | 最新 60 条或不足提示明确，分类依据符合模式，来源可追溯 |
| AC-06 | 转写成功/失败、分别分析开头和结尾 | 两种范围不串缓存，真实转写与发布文案有来源标识，缺失不编造 |
| AC-07 | 合并多个账号到正式库、重复纳入、员工尝试写库 | 各账号分类独立，重复源不重复建库，员工写入被拒绝 |
| AC-08 | 读取客户规划与跨经理访问私人报告 | 员工允许按客户读取，私有报告不能被任意 ID 绕过 |
| AC-09 | 筛选点赞 99、100、101 的更新视频 | 仅 101 通过既定 `>100` 门槛；勾选不改写正式库 |
| AC-10 | 按客户二创、切换选题、复用脚本和结构 | 客户上下文正确，各选题结果独立，候选条数符合配比 |
| AC-11 | 配置封面、出图途中换选题、连续改图 | 缺素材准确提示，完成图片仍归发起选题，修改针对指定候选 |
| AC-12 | 发布仓复用文案、核查并导出/写入 | 标题与三秒来自已选内容，缺项可见，导出关联正确，失败可恢复 |
| AC-13 | 不上传 Excel，分别填写 4.1 与 4.2 | 两种分析均可完成；周度可增删视频，零值与缺失区分 |
| AC-14 | 常规/横向/带说明/多工作表 Excel 识别后修改 | 来源取值正确，工作表和单视频选择正确，报告使用修改后的数据 |
| AC-15 | AI 返回伪造数值、重复映射或越界位置 | 不使用生成数值；非法位置拒绝，已有表单数据保留 |
| AC-16 | 百分比格式、`32%`、小数、万单位、Excel 日期、汇总行 | 正确归一化且无二次百分比换算，日期正确，汇总跳过并提示 |
| AC-17 | 分别测试 200、500、1000、1001、10000、10001 播放 | 流量池边界正确，`=1000` 独立呈现，未定义区间有说明 |
| AC-18 | 周度含重复 ID、周期外视频、缺专业指标、少量样本 | 重复拒绝；排除原因可见；缺失不按零统计；弱证据明确 |
| AC-19 | 前周缺失或名称/客户/平台不同的历史报告 | 不生成错误环比，只比较相同有效范围 |
| AC-20 | 修改下周计划、配比并预览 | 大类条数等于计划，小类等于大类，结构每组十条，各组比例归一 |
| AC-21 | 保存周报但不确认，再确认后查看选题/二创 | 保存前后策略不变；确认后相关范围使用新版本和经理经验 |
| AC-22 | 连续确认两版、重试旧请求、停用后再重试 | 当前指针不被旧请求覆盖，停用版本不复活 |
| AC-23 | 删除来源周报、查看经验历史及停用回退 | 经验仍在；停用后生产读取基准库，不修改原始研究统计 |
| AC-24 | 按配比勾选而某分类候选不足 | 返回具体缺额，不用其他类别补齐；平台策略不混用 |
| AC-25 | AI/转写/出图/飞书不可用，桌面及手机操作 | 不显示虚假成功，已有输入/材料保留，可用手工路径继续，无运行错误 |

### 现有测试基础与质量验收

项目已经具备指标纯函数、Excel 解析、分类/结构归一化、配比换算、Mongo 持久化、报告权限、路由冒烟和页面渲染测试，可用于上述验收。周报确认版本与 Excel 来源取值已有专门边界测试，继续复用这些测试面。

模型质量验收使用业务人员提供并人工标注的样本，分别检查字段识别、标签一致性、引用来源、建议事实性及可执行性；记录错误样例，不预设未经确认的准确率。二创验收另看客户身份、事实、表达质量和配比落实，不能仅凭模型请求返回成功判为通过。

## Out of Scope

- 自动登录短视频平台并直接发布、自动抓取客户私有后台数据；本版依赖人工发布和手工/Excel 录入自有数据。
- 无需人工审核就自动改变团队策略或让所有分析结果进入“记忆”。
- 承诺爆款、粉丝或收入增长，或者将周度相关性当成经过验证的因果结论。
- 重新建设与现有模块重复的账号定位、选题库、鉴权、数据库或工作台。
- 客户独立登录门户、商业化订阅、支付、完整多组织 SaaS 隔离体系。
- 任意格式、任意大小的表格识别，旧 `.xls` 直接解析，扫描图片/OCR 和新增文件类型解析。
- 同一客户同平台多个自有账号的独立生效记忆；当前继续用客户＋平台作用域。
- 跨账号覆盖原始分类、自动合并正式库全部分类，以及未确认的自动写库链路。
- 独立标题研究库、由 4.1 自动确认策略、自动更新平台标准值。
- 为全部页面增加跨设备实时协作、全量离线能力或持久化草稿；仅保持现有已支持行为。
- 扩展所有短视频平台至相同能力水平；本版新复盘以抖音和视频号为范围，其他已有入口保持兼容。
- 本 PRD 发布本身不包括生产部署、数据库迁移、线上配置变更或代码提交。
